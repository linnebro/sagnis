# Sagnis for Microsoft 365 Copilot Cowork

The same system, on a harness with no shell, no git and no `AGENTS.md`. What
Sagnis needs is a folder the assistant reads first and writes to last; Cowork has
one (your OneDrive `/Documents/Cowork/`), and it reads `SKILL.md` files from it at
the start of every session. That is enough.

Written against Microsoft Learn as of 2026-09-14. Untested on a live tenant; if
you install it, [say where it stalled](../../../../issues/new?template=install-stall.md).

## What maps to what

| Coding-agent build | Cowork build |
|---|---|
| `~/.claude/AGENTS.md` (global instructions) | **Customize > Preferences**, the paste-ready block in `PREFERENCES.md` (20 KB cap; keep it well under, it is loaded on every task) |
| `~/.claude/skills/sagnis/SKILL.md` | `/Documents/Cowork/skills/sagnis/SKILL.md`, discovered at the start of each session |
| Master space `~/.claude/` | `/Documents/Cowork/` in OneDrive |
| Project space (a repo with a two-line shim) | The tenant itself: your mailbox, calendar, Teams and the SharePoint sites you can reach. Nothing to install there. |
| `knowledge/MEMORY.md`, generated by `build_index.py` | `knowledge/MEMORY.md`, **kept by hand** by the assistant, same shape (Recent + Routes) |
| Topic `INDEX.md`, generated | Topic `INDEX.md`, kept by hand, same shape |
| Mirror index of a repo folder | Mirror index of a SharePoint library or Teams channel: one `INDEX.md` per source that matters, one line per document |
| `journal/` one file per session | Same |
| `TASKS.md` generated from initiatives | `TASKS.md`, a hand-kept table with a clean-runs column (below) |
| `RULES.md` with "rules that have bitten" | Same |
| Commit and push in the same turn | OneDrive syncs; there is nothing to commit. OneDrive version history is the undo. |
| Scripts and scheduled jobs | Scheduled prompts and event-driven tasks, and only after a task has been run by hand three times clean |

Everything Cowork has that a coding agent does not (a production mailbox, a
production Teams, other people's files) makes the guardrails matter more, not less.
The Preferences block and `RULES.md` are written for that: draft first, ask before
every write, treat what it reads as data.

## Install (15 minutes, from a desktop browser; custom skills are not supported in Cowork on mobile)

1. **Copy `master/` into OneDrive** as `/Documents/Cowork/`. Merge if the folder
   exists; nothing here overwrites a file Cowork made. You get `knowledge/`
   (`MEMORY.md`, `general/`, `work/`, `journal/`) and `skills/sagnis/SKILL.md`.
2. **Rename `work/`** to the thing you do (`security-program`, `sales-ops`,
   `finance`), inside the folder and in the two places `MEMORY.md` names it. One
   topic per area of your job; start with one.
3. **Paste `PREFERENCES.md`** into Customize > Preferences, brackets filled. Every
   line must be true for you; delete what is not.
4. **Open a new conversation** and say: *learn the environment, read-only*. The
   skill writes what it finds as one fact per file with the source, and updates the
   indexes. Read them. Correct them. That is the memory base.
5. **Start every conversation** with *read MEMORY.md first*. The Preferences block
   says so too; saying it costs nothing and the first week is when it matters.

## Hand-maintained indexes, and the script upgrade

There is no `build_index.py` run inside Cowork, so the skill keeps the indexes by
hand and the shapes in `master/` are the contract: one line per fact,
`date [Title](file) — description`, newest first, grouped by type. The tree is laid
out exactly as the generated build expects (`TOPIC.md` per topic, frontmatter on
every fact), so if the OneDrive folder is synced to a machine with Python you can run

```
python sagnis/scripts/build_index.py --knowledge "<OneDrive>/Documents/Cowork/knowledge"
```

and it regenerates the same files, dating facts as today where there is no git
history. Do that when the hand-kept index drifts, or weekly; the assistant's edits
and the script's output are the same format. Cowork's docs mention script execution
for some background work; whether it will run this script itself is untested.
Assume not.

## Tasks, and the road to automation

`knowledge/work/TASKS.md` is a table, not a roster from initiative files: id, task,
what it reads, what it writes or sends, what could go wrong, status, clean runs. The
last column is the whole automation policy. A task becomes a scheduled prompt or
an event-driven task only at three runs without a correction, and only if it never
sends or posts to anyone but you. The skill can add rows and update counts; only
you change a status to approved.

## What is not here

The audit trail (the tenant's unified audit log already records every prompt,
response, skill load and scheduled run). `init_workspace.py` (the `master/` folder
is the scaffold). `measure.py` (no shell; the before-number is how often the
assistant re-searched for something it had already found).
